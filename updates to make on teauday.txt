# DISHI App — Full Fix & Feature Implementation Plan

## Overview
This plan addresses all reported bugs, permission errors, UI overflows, mock data replacements, and new feature additions across the DISHI Flutter app. Work is broken into **7 phases** ordered by dependency (infrastructure first, then features).

---

## Phase 1 — Firebase Infrastructure & Security Rules
**Goal:** Fix all Firestore/Storage permission-denied errors that block event creation, event dashboard, virtual card, and other features.

### Root Cause
The `events` collection is written to in `create_event_view.dart` but has **no rule** in `firestore.rules`. Similarly, `card_transactions`, `virtual_cards`, `transport_*`, `harambee_campaigns`, `subscriptions`, `safter_pins`, and `digital_ledger` collections are missing rules. Storage paths for `events` are already present but some paths used by app code differ.

### Changes

#### [MODIFY] [firestore.rules](file:///c:/Users/Delstaford/swapeat/firestore.rules)
Add the following missing collection rules:
- `events/{eventId}` — any authenticated user can create; creator or admin can update/delete
- `event_tickets/{ticketId}` — any auth user can read/create; involved parties can update
- `card_transactions/{txId}` — owner can read; backend creates
- `virtual_cards/{uid}` — owner reads/writes own card
- `transport_sessions/{sessionId}` — any auth user read/write
- `transport_bookings/{bookingId}` — owner read/write
- `harambee_campaigns/{campaignId}` — creator can CRUD; others read; auth users create donations subcollection
- `harambee_donations/{donationId}` — any auth user create; creator reads
- `subscriptions/{subId}` — owner read/write
- `safter_pins/{pinId}` — already exists; verify `safety_pins` vs `safter_pins` naming clash and normalise
- `digital_ledger/{entryId}` — owner read/write/delete (swipe-to-delete)
- `flashcards/{cardId}` — any auth user read; admin write
- `quizzes/{quizId}` and `quiz_submissions/{subId}` — read for all auth; write for admin
- `campus_feed/{postId}` — any auth user read/write (reactions, replies)
- `campus_feed/{postId}/comments/{commentId}` — any auth user read/write
- `driver_transport/{driverId}` — driver reads/writes own; students read
- `maintenance_reports/{reportId}` — any auth user read/create; involved parties update

#### [MODIFY] [storage.rules](file:///c:/Users/Delstaford/swapeat/storage.rules)
Add/fix:
- `/harambee_images/{imageId}` — public read, auth write
- `/campaign_images/{imageId}` — public read, auth write
- `/flashcard_images/{imageId}` — public read, admin write
- `/quiz_images/{imageId}` — public read, admin write

### Verification
Deploy rules via `firebase deploy --only firestore:rules,storage` and re-test event creation. Expect no permission-denied error.
